Crumb Writer
============

Version 2.0. Programmed by ChatGPT for Alfredo Llaquet-Alsina.

Build, update and launch
------------------------

Crumb Writer is a C++17 and Qt 6 desktop editor for FreeBSD 15 or later and
KDE Plasma 6 or later. It also builds on Linux. Qt Widgets provides the
editor and its windows. Qt Network handles local application activation.
The C parser and disk modules use GLib/GIO. GLib also provides the PCRE
search interface. FreeBSD's base C and C++ compilers and make build the
program. Install the following packages as root.

    pkg install git pkgconf glib qt6-base

For a first checkout, run these commands as the desktop account.

    git clone https://github.com/AlfredoLlaquet/crumbwriter.git
    cd crumbwriter
    make
    ./crumbwriter

To update a checkout, close the running Crumb Writer windows first. From the
existing repository directory, run the following commands. The Qt 6 package
above is required when upgrading from version 1.4.

    git pull --ff-only
    make
    ./crumbwriter --version
    ./crumbwriter

A path can be supplied directly. Several paths open separate manuscript
windows. An explicit filename takes precedence over the last-document setting.

    ./crumbwriter /path/to/Crumbs.txt

On a fresh launch, the default is to reopen the last named manuscript. A first
launch opens an untitled document. Ctrl+O opens a manuscript, and Ctrl+Shift+N
opens a new untitled window. Opening places the caret at the end of the file's
content, just before a final newline when present. The opening view shows
the preceding crumbs that fit in the editor. Opening the same file again
raises its existing window and returns to that writing position.
Launching again without a filename reactivates a window at its current caret.

Run make install as root to install the executable, manual, Plasma launcher
and icon under /usr/local. A per-account installation uses the following
command, with $HOME/.local/bin on PATH.

    make install PREFIX="$HOME/.local"

Repeat the installation after upgrading an installed launcher. DESTDIR can
stage either installation for packaging. Linux uses the same make targets
with a C++17 compiler, pkg-config, Qt 6 base development tools and GLib/GIO
development headers. The icon comes from the official Crumbs website's
favicon. The Wayland application ID and desktop file share the identifier
org.thecrumbs.CrumbWriter. Installed icons and Qt's embedded icon contain
the original sizes from 16 to 256 pixels.

The manuscript and word count
-----------------------------

Each physical line holds one crumb. The first two field-separating colons
delimit the header, title and body. A numbered header has a label, a space
and a positive decimal number. Titles and bodies can be empty. Later colons,
verse separators, URLs and inline-footnotes inside ‹{ }› belong to the text.
A first-line work title can precede the header and end with //. An unfinished
line stays editable. A word-wrapped crumb still occupies one file line.

By default the writing font is proportional Serif at 14 points. Headers are
italic, titles bold and bodies normal. The writing area always wraps to the
available editor width. Moving the window edge, tiling it or moving the
sidebar divider gives the text its new width. Long unbroken words can wrap
inside narrow tiles. Scrolling and jumps are immediate.

The sidebar shows the current crumb's header, title and word count. The count
includes the header, title and body, with the first work title through //
excluded for an individual crumb. Replace each em dash with a space, then
each non-overlapping literal " / " with one space, and count using the host
wc -w convention for the active locale. Hyphenated words and attached slashes
otherwise retain their characters. The reference command for the entire file
includes the work title and replaces its first // separator with one space.

    sed -e '1s@//@ @' -e 's/—/ /g' -e 's@ / @ @g' Crumbs.txt | wc -w

"Crumb 2: : " counts as three words. The session total counts distinct valid
header numbers currently present that were absent when the manuscript opened.
Appending, editing, pasting, deleting and undoing update the total. Each
manuscript window has its own opening baseline, history and undo stack.

Appearance and editing
----------------------

The active crumb has a very light blue band across its wrapped lines. A dark
theme receives a subdued blue tint. A search selection has its own foreground
and background. Focus in the sidebar, Find or Replace belongs to the manuscript
window. When another window becomes active, this manuscript's paper turns
light gray (#e5e5e5) with dark text. The active window restores its normal
paper when focus returns. Settings offers Desktop, Light and Dark, a font
family and a point size between 6 and 96. Font changes affect the display.

Ctrl+N appends the last recognizable label and one greater than the largest
valid header number. A fresh manuscript starts with Crumb 1. An empty title
produces "Crumb 42: : " with the caret after the final space. A work title
ending in // can take the first header on that same line. Existing terminal
line breaks follow the newly appended crumb. One Undo removes the new record.

Typing "Haiku #" in a title completes the next number from the nearest
earlier Haiku. The typed genre spelling is preserved. With no previous
occurrence, the hash remains available for writing. A hash in a body is
literal. The alphabetized Genres list shows the most recent number of each
genre. Activating "Portrait #42" appends a new crumb titled "Portrait #43"
and focuses the body. F7, a fragment of the genre name, and Enter do the
same from the keyboard. A title such as "Negation #10, Confession #3" indexes
both components. "Fingers (Haiku #157)" also contributes to Haiku.

Bold red digits flag a header whose number differs from its one-based
physical line, or a numbered genre that breaks its sequence. The first
occurrence of each genre expects 1. Subsequent occurrences use the previous
written ordinal plus one. In Haiku #1, #3, #4 the 3 is flagged and the 4
follows normally. Blank or unfinished physical lines count toward header
line numbers. F4 and Shift+F4 visit the next or previous warning, select
the digits and show the expected and actual values. Saving preserves the
written numbers.

Tabs and runs of ordinary spaces become a single ASCII space. Pasting
normalizes the whole insertion and its edges in one undoable edit. Newlines,
blank lines and nonbreaking spaces are preserved. A space typed at the end of
a crumb stays available for the next word, including across a live save.
Leaving the crumb or beginning a search trims a pending trailing space. Saved
manuscripts, drafts and copied crumbs omit trailing ASCII spaces and tabs.

Smart punctuation operates on typed keys and committed input-method text.
A following character supplies context for straight quotation marks and
apostrophes. Typing the t in Don't produces Don’t. Typing a space after
Pepe," produces Pepe,” and the space. Typing the s in new--s produces new—s.
Three periods become … when the sequence is resolved. Moving the caret,
leaving the editor, an explicit save, or closing the document resolves
pending punctuation. A paste or search replacement keeps its literal
punctuation. Settings can disable smart punctuation. Curly punctuation
belongs to the saved UTF-8 text.

The visit list records crumbs in order of last visit and shows their numbers
and titles. A visit points to the actual crumb and caret, so duplicate header
numbers can have different destinations. Click an entry or press F6, type a
title fragment, and press Enter. F2 and Shift+F2 move back and forward among
deliberate jumps. One search records a single return position while its query
is refined. Ctrl+Shift+J follows the reference under the caret in either
"crumb 200" or "see crumb 200". Matching ignores case and recognizes the
current crumb's particular label. F2 returns to the original word.

Navigation and window keys
--------------------------

    Up / Down                Previous / next wrapped visual line
    Home / End               Start / end of that visual line
    Tab / Shift+Tab          Next / previous header, title or body
    Ctrl+Up / Ctrl+Down       Previous / next recognizable crumb
    Ctrl+Home / Ctrl+End      Start / end of the current crumb
    Ctrl+Page Up (RePág)      Start of the entire file, including any work title
    Ctrl+Page Down (AvPág)    End of the entire file, including any final newline
    Ctrl+Enter / Alt+Enter    Center the caret line / put the crumb at the top
    Ctrl+N                   Append a crumb when Find is closed
    Ctrl+1                   Select and copy the header, such as "Crumb 42"
    Ctrl+Q                   Select and copy the current crumb
    Ctrl+Y                   Delete the current crumb with manuscript focus
    Ctrl+Z / Ctrl+Shift+Z     Undo / redo
    Ctrl+A / Ctrl+X           Select all / cut selection
    Ctrl+C / Ctrl+V           Copy selection / paste
    Escape                   Clear the selection and close Find when visible
    F2 / Shift+F2             Back / forward after a deliberate jump
    F4 / Shift+F4             Next / previous numbering warning
    Ctrl+Shift+J / Ctrl+L     Follow a crumb reference / go to a crumb number
    F6 / F7                  Focus visit history / genres
    F9                       Show or hide the sidebar
    Ctrl+B / Alt+B            Add a named bookmark / open Bookmarks
    Ctrl+O / Ctrl+Shift+N     Open a manuscript / create an untitled window
    Ctrl+S / Ctrl+Shift+S     Save / Save As
    Ctrl+W                   Close the window when Find is closed
    Ctrl+, / F10 / F1         Settings / document menu / keyboard reference

Ctrl+1 includes the original label and digits through the end of the header.
The colon and optional work title are outside the selection. Ctrl+Q selects
through the end of the crumb's body, excluding its terminating newline and
any first-line work title. Both operations copy plain text and leave the
copied span selected. Ctrl+Y deletes the crumb at the caret in one edit,
preserving the work title and the file's final-newline convention. It is a
manuscript shortcut. Typing in Find, Replace or the sidebar cannot invoke
that deletion through Ctrl+Y.

Down or a click below the document can place the caret on a virtual row.
The sidebar identifies its potential physical line. Navigation in this space
changes no manuscript bytes. Typing or pasting there materializes the needed
line breaks and text in one undoable edit. An existing final newline already
starts a physical empty line. Escape returns to the physical end. Ctrl+Enter
centers the current wrapped line, including the last one. Alt+Enter places
the current crumb's first wrapped line at the top while preserving its caret.

Search and replacement
----------------------

Ctrl+F opens forward Find from the manuscript caret. Ctrl+G opens backward
Find from the same position. Plain-text input immediately selects the nearest
match in the opening direction and centers its starting visual line. Each
refinement starts at the original search caret. Clearing the query or
refining it to a missing match after a preview returns to the origin. Escape
closes the panel, clears the selection and returns focus to the manuscript.

Ctrl+H opens Find and Replace. Further Ctrl+H switches keyboard focus between
Find and Replace with, keeping both values. Ctrl+L opens direct number
navigation. Enter a positive number and press Enter. The number index handles
the optional first-line prefix, alternate labels, duplicate numbers, direction
and wrap. A bookmark goes to a physical line. A number search goes to a
matching header. Replacement is available in plain-text and regex modes.

    Ctrl+P / Ctrl+R / Ctrl+N   Plain text / regular expression / crumb number
    Ctrl+M / Ctrl+W / Alt+W    Toggle match case / whole words / wrap
    Alt+Down                  Show recent searches and focus the list
    Enter / Shift+Enter       From query, repeat forward or back relative
                              to the opening direction
    F3 / Shift+F3             Repeat in the opening / opposite direction

F3 and Shift+F3 also work with the panel closed. After Ctrl+G, F3 goes
backward. After Ctrl+F or Ctrl+H, F3 goes forward. Find shortcuts apply
while the panel is visible, including when focus is back in the manuscript.
Completed queries retain their mode and options in recent searches. Arrows
and Enter recall a search. Repeating an identical query and options moves
that entry to the top. The Qt version reads existing 1.4 search history.

Text and regex start case-insensitive, with wrapping at file ends. Regular
expressions use GLib's PCRE syntax with multiline anchors and ungreedy
repetition. A dot matches a single character except a newline by default.
The following expressions can be typed directly in the Find field.

    Haiku #[0-9]+:         A numbered Haiku title through its colon
    “.*”                   A single curly-quoted passage on one line
    (?-U)“.*”              Through the last closing quote on that line
    ‹\{.*\}›               An inline-footnote with its literal braces
    ^Crumb ([0-9]+):       Capture a number in a header at the start of a line

An optional work-title prefix precedes the header on line 1. In regex
replacement text, \1 inserts the first capture. Plain-text replacement
treats its replacement literally. All… displays the number of replacements,
the number of affected crumbs, and up to four before-and-after examples.
Apply all executes the preview as a single undoable edit. Changes to the
manuscript, query or replacement invalidate the preview.

    PCRE2 syntax       https://www.pcre.org/current/doc/html/pcre2syntax.html
    PCRE2 patterns     https://www.pcre.org/current/doc/html/pcre2pattern.html
    Replacement text   https://docs.gtk.org/glib/method.MatchInfo.expand_references.html

Named bookmarks
---------------

Ctrl+B bookmarks the current physical line. Each bookmark has a category and
a name. The default category on first use is General. The next add remembers
the previous category, so Ctrl+B followed by Enter adds its next numbered
bookmark. A category starts numbering at 1. A manually assigned positive
decimal name such as 7 can advance its counter. Deleting a numbered bookmark
preserves the category's counter. Names are unique inside a category.

Alt+B opens a separate modeless Bookmarks window for that manuscript. Tree
view presents categories and names. A category with one bookmark opens that
line directly. List view displays category, name, physical line and the
current crumb title. Filter matches category, name, line and title, ignoring
case. Separate words can match different columns. Enter opens the selected
bookmark and returns to the editor. A bookmark stored for 200 always opens
physical line 200, including after an insertion above it. An out-of-range
entry reports its line and stays available if the manuscript grows again.

Inside Bookmarks, Ctrl+F focuses Filter. The arrow keys reach the results.
F2 on a result edits its name or category, Delete asks before removing the
selection, and F5 reloads the companion file. In the manuscript window, F2
continues to mean Back.

A manuscript named Crumbs.txt uses Crumbs.txt.bookmarks in the same directory.
The companion file is ordinary indented UTF-8 JSON. Its version-1 structure
contains the last category used, persistent category counters and bookmarks.
For example, the following is a complete bookmark file.

    {
      "version": 1,
      "lastCategory": "Revise",
      "counters": {"Revise": 1},
      "bookmarks": [{"category": "Revise", "name": "1", "line": 200}]
    }

The title comes from the current manuscript and updates when that line's title
changes. Bookmark edits to a named file use a lock, compare the disk bytes and
publish atomically. An untitled manuscript keeps pending bookmarks in memory.
A successful Save As copies its bookmarks beside the new manuscript. A
conflicting destination companion file produces a notice and keeps the copy
pending for recovery or retry. Reloading rereads changes made by another
editor. The bookmark file is independent of the manuscript's UTF-8 bytes.

Saving, closing and recovery
----------------------------

By default an existing manuscript receives a private backup in its own
directory before editing. The backup preserves the original bytes, including
a BOM, mixed line endings and original whitespace. Each opening gets a
unique filename, for example Crumbs.txt.YYYYMMDD-HHMMSS-xxxxxxxx.bak.

Manuscripts and drafts are written as UTF-8 without a BOM. Invalid UTF-8
and embedded NUL bytes are reported at open. File loading accepts LF, CRLF
or CR and exposes LF to the editor. Saving retains the existing line-ending
convention and final-newline state. The storage layer preserves mixed endings
when matching existing lines. It also keeps adjacent CR and LF separators
distinct when an intervening whitespace-only line is cleaned. Ctrl+S can
strip an input signature and normalize spacing even on an untouched document.

Live saving defaults to one second from the first outstanding edit. Settings
can choose a delay from 1 to 30 seconds or manual saving. The GUI captures the
current text once per write. A worker per document performs UTF-8 encoding,
spacing cleanup, external-change verification and disk I/O. The editor can
accept new typing during this work. Each completed write acknowledges only
the revision that was actually saved. Later edits remain pending.

Before replacing a file, the writer checks its identity and exact disk bytes,
writes and synchronizes a temporary sibling, then publishes the replacement.
New destinations use exclusive creation. Existing local symlink targets are
resolved on open. A failing or externally changed manuscript displays a
notice and keeps the working copy. Ctrl+S retries, and Ctrl+Shift+S saves it
under a new name. A failing manuscript write attempts a private recovery
draft. With live saving enabled, untitled documents also receive drafts under
$XDG_DATA_HOME/crumbwriter/drafts or ~/.local/share/crumbwriter/drafts.
Recovery drafts reopen as unsaved manuscripts at the next launch.

Closing with queued edits, an active write, a save failure or pending bookmarks
opens the Unsaved Changes dialog. A fully saved document closes directly.

    Save and Close          Save the latest edits, then close on success.
                            An untitled manuscript opens Save As.
    Discard Unsaved Changes Drop pending edits and remove the recovery draft.
                            Previously committed edits remain on disk.
    Keep Editing            Return to the manuscript. Escape chooses this.

The close confirmation pauses automatic saves. Discard can cancel a write
before the atomic publish point. A prior live save, or an in-flight write
already past that point, is already on disk. The startup backup retains the
pre-session bytes. A failed Save and Close keeps the window available.

Implementation and maintenance
------------------------------

The default make target builds the Qt application. Each physical manuscript
line maps to one QTextBlock. Qt cursor offsets use UTF-16 code units, disk
operations use UTF-8 bytes and the C parser counts Unicode code points.
Convert at the model boundary. The plain-text snapshot preserves nonbreaking
spaces and converts document paragraph boundaries to LF. Only the disk layer
reintroduces physical line endings. Formatting and search highlights stay
outside the manuscript text.

The manuscripttext adapter preserves literal U+2029, U+FDD0 and U+FDD1,
which Qt uses internally for document structure. Reading spans through this
adapter keeps file bytes, clipboard text and search positions consistent.

    src/qt/main.cpp, application.*         Command line, desktop ID and icon,
                                           local single-instance activation,
                                           recovery and manuscript windows
    src/qt/mainwindow.*, windowcommands.cpp Window actions, focus, closing,
                                           opening, save and bookmark wiring
    src/qt/preferences.*                   Shared settings and F1 reference
    src/qt/navigation.*                    Current metrics, visit history,
                                           genre list and back/forward marks
    src/qt/crumbmodel.*                    Per-line records, words, ranges,
                                           number and genre indices, warnings
    src/qt/manuscripteditor.*              Qt writing control, formatting,
                                           crumb editing and caret commands
    src/qt/editorinput.cpp                 Key/IME input, paste, undo groups,
                                           spacing and genre completion
    src/qt/committedpunctuation.*          Context for smart punctuation
    src/qt/editorviewport.cpp              Painting, paper, virtual rows,
                                           scrolling and visual positioning
    src/qt/searchpanel.*                   Find, navigation, preview, focus
                                           and visible match highlighting
    src/qt/searchengine.*, searchhistory.* Matching, replacement expansion
                                           and stored queries with options
    src/qt/bookmarks.*, bookmarkfile.*     Modeless bookmark UI and atomic
                                           versioned JSON companion files
    src/qt/documentstore.*                 Revisioned save queue, worker,
                                           recovery and close coordination
    src/crumb.c, spacing.c                 Tested UTF-8 grammar, word count
                                           and canonical horizontal spaces
    src/storage.c, draft.c                 POSIX verified file replacement,
                                           backups, newline maps and drafts
    data/crumbwriter.qrc, data/icons/      Embedded and installed icons
    Makefile, .github/workflows/check.yml  Build, install, test and platform CI

Each manuscript has one QPlainTextEdit with a QSyntaxHighlighter. It follows
the widget width. A Qt plain-text layout computes visible paragraphs at the
current width. The background band is painted over visible wrapped rows.
Whole-file regex scans and replacement planning can run in the background.
Stale results are invalidated when the query or document changes.

On the Linux/X11 test machine, Xfwm tiled the complete editor from
1050 x 680 to 672 x 990 with the last of 3,371 crumbs on screen. In two
unedited trials, version 2.0 drew the resized manuscript in 18.48 ms and
14.69 ms. The process used 0.02 and 0.03 CPU seconds across the respective
observation windows of 2.15 seconds. In version 1.4 the same window resize
used 1.83-1.90 CPU seconds. Ten characters typed during a separate tile reached
the last crumb on disk through normal live saving. These are Linux software
paint measurements. The resize test also runs natively on FreeBSD and
prints its own results for 3,371 and 25,092 synthetic crumbs.

The model uses each edited range from QTextDocument. A same-line change
reparses that line, and a genre edit revisits affected successor warnings.
A change to physical line numbering reuses the parsed records for unaffected
text. Header lookups use duplicate-aware sorted positions, and genre
completion finds the nearest earlier occurrence. Visit history and jump
history use positions that track editing. Saved bookmarks use fixed,
one-based line numbers. These three forms of navigation have different
lifetimes.

Settings live in $XDG_CONFIG_HOME/crumbwriter/settings.ini or
~/.config/crumbwriter/settings.ini. The last document is a local file URI.
Local single-instance forwarding uses a user-scoped socket and lifetime
lock in Qt's runtime directory. The system window manager controls geometry
and decorations. The attached F1 reference, Settings and bookmark windows
can stay modeless while the manuscript is open.

Verification
------------

Use make check-core for the parser and storage tests without a display. In a
graphical session, make check runs the core and Qt suites. make check-gui
runs the model, document store, bookmarks, editor, search, window and resize
tests. The resize test measures a completed paint after typing in a moving
window and checks the actual text and caret.
The same Makefile supports FreeBSD base make and GNU make.

For a counting change, compare each valid Qt model record against sed and
wc in the target locale. tests/qt/test-model /path/to/Crumbs.txt prints
one-based line numbers and counts for a supplied manuscript after its model
checks. Exclude the work-title prefix when checking the first individual
crumb. Exercise supplementary-plane characters, combining marks, alternate
labels, repeated header numbers, compound genres and abbreviated drafts.

Use disposable files for typing and storage tests. Check the bytes of
startup backups and UTF-8 output, all supported newline styles, an input
BOM, external edits, a failed write, a new edit arriving during a save and
each pending-close choice. Test bookmark companion writes independently,
including Save As and externally changed JSON.

Test the writing window under actual Plasma/Krohnkite tiling and native
Wayland input. Resize a window while typing in the last crumb of a large
manuscript. Verify the entered text and saved bytes, caret visibility and
centering, current-crumb band and immediate scrolling. A first text paint,
key-to-paint delay and CPU consumed after resizing measure different costs.
The desktop checks live in tests/check-krohnkite.py and tests/check-wayland.py.
The tiling check reads window geometry from X11 and samples the active and
inactive paper colors with tests/sample-x11-paper.c.

Update this manual in the same change as each modification to Crumb Writer.
Update README.md and the in-app shortcut reference when controls, platform
dependencies or build commands change.

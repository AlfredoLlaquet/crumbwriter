Crumb Writer
============

Version 3.1. Created and directed by Alfredo Llaquet-Alsina. Implemented by ChatGPT.

Version 3.1 implementation guide
--------------------------------

Software Project Working Rules
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Use a single agent throughout a project. Design for human developers and
future AI maintainers. Give each component a recognizable purpose and make
its behavior, dependencies and decisions explicit enough to change safely
with limited surrounding context. Favor meaningful modularity, consistent
conventions and traceability. Avoid unnecessary abstraction, fragmentation
and duplication. Keep extensive, navigable project documentation current in
the same change as the code. Explain the requirements, architecture,
rationale, conventions and verification. After implementation and testing,
review the work against the original specification. Correct substantive
defects, omissions and inconsistencies. Finish after that review and the
documentation update, without speculative or purely stylistic changes.

Menus, writing tools and editing
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
windowcommands.cpp builds File, Edit, View, Format, Navigate, Tools, Window
and Help, retaining the writing toolbar. formattingtoolbar.cpp synchronizes
Font, size and Style with the active document. In Generic mode the first
line offers Main Title or Regular Text. Subsequent lines offer Regular Text
or Title 1 through Title 4. Use Ctrl+Shift+K followed by M, 0 or 1–4.
ManuscriptOptions changes the heading marker and saves explicit first-line
title detection in the manuscript's .config. The native text remains portable.
In normal view heading-marker rows and on-screen heading underlines are
hidden. Ctrl+Shift+F9 reveals them. editorviewport.cpp measures the shaped
title and scales the repeated marker glyphs to its displayed width.

Generic mode initially hides Characters. View > Characters remembers a choice
in each mode. Recurring is independent. Right-clicking a list entry selects
the clicked row and opens its applicable commands. Ctrl+. uses SpellCheck's
word-at-caret lookup and offers Hunspell suggestions for that occurrence.
F8 retains the normal spelling review. The dictionary actually loaded is en_US.
editorinput.cpp preserves a run of inter-word spaces during an edit and
normalizes it when the caret leaves. Ctrl+Left/Right stop on both sides of an
em dash connecting words. genericlist.cpp records a generated prefix so an
explicitly typed or pasted marker can replace the proposal once.

Documents and sessions
~~~~~~~~~~~~~~~~~~~~~~
Use + beside the tabs or double-click unused space on the strip to open a
blank document. workspacestate.cpp records tab order, active tab, named file
or private recovery path, selection and scroll in the local settings.
application.cpp restores windows on cold start; documents supplied on the
command line still activate their own tabs. A missing file produces a notice.
Closing through File > Quit preserves windows together. Keeping an untitled
draft waits for its latest text and companions. Explicitly discarding it
removes its recovery record.

File > Import makes a new editable untitled manuscript. fileconversion.cpp
owns the dialogs and encoding preview. documentformats.cpp handles strict
GLib character conversion, fixed-width text, PDF and Qt document formats.
officeformats.cpp reads Office XML directly from ZIP entries and writes DOCX.
rtfimport.cpp reads RTF and pdfimport-macos.mm uses system PDFKit. Other
platforms run pdftotext as a separate process. Scans need OCR. formatprose.cpp
translates the editor's heading levels, body type and italics into formatted
copies. File > Export supports DOCX, ODT, PDF, HTML and plain text in a chosen
encoding. The 80-column option wraps text and doubles a single space after a
period. Export uses a temporary file and commits only on success.

Source map and maintenance notes
--------------------------------------------

For manuscript syntax and examples see “Writing novels and other prose in
Generic mode” below and README.md. The searchable F1 guide lists commands
by task. File formats, dependencies, publication and desktop checks follow
the writing reference. AGENTS.md contains the standing maintenance rule.

README.md opens with the writing experience. Generic mode comes first, with
examples of headings, italics, lists, word lookup, and tracking names across
a document. The companion-file table uses Harbor.txt to show what to copy
when moving to another computer. “Write your own crumbs” introduces the form
to new writers. Alfredo’s collection and its Crumb Reader at TheCrumbs.org
show how a plain text file can become a published work.

In the reader guide, use “document” for an open work, “plain text file” for
what is saved, “writing area” for the editor, and “cursor” for the typing
position. Use literary terms where they fit the example and keep names such
as Manuscript Settings, Manuscript Dictionary, and Manuscript Statistics
when directing readers to those windows. The README’s “Plain text file
format” section covers the shared encoding, file lines, and mode detection.
When editing the guide, check its heading links, examples, and companion
filenames. tests/test-release-assets.py checks the versioned download links.

* MainWindow and manuscripttabs.cpp manage windows, tab order, path reuse,
  close confirmation and reopening. ManuscriptSession owns one editor, its
  store and its search, navigation, spelling, bookmark and companion tools.
  The window shows the active session’s controls. Duplicate detection covers
  the named document and its live private recovery draft. ManuscriptPath
  compares the filesystem identity of existing targets, including aliases,
  and normalized destinations for prospective saves. Unrelated missing files
  each take their own error path. Resetting the layout
  restores the default sort for every open tab’s Titles or Genres panel.
  Move Tab to New Window
  moves the live session. It preserves undo and outstanding background work.
  Shared panel typography follows the application font independently of the
  manuscript font. Closing a file picker returns the keyboard to its editor.
  Ctrl+T opens a blank tab, Ctrl+O opens a file, Ctrl+Tab and Ctrl+Shift+Tab
  cycle in display order, Ctrl+F4 closes and Ctrl+Shift+T reopens. Ctrl+N
  appends text, Ctrl+W erases a word and Alt+W closes a window.

* manuscriptoptions.cpp shares TextCompanion’s lock, baseline check and
  atomic write. A manuscript named Harbor.txt can use Harbor.txt.config,
  a UTF-8 key=value file. disable-general-title=true and literal-guillemets=true
  independently override the defaults (both false). Blank lines, comments
  and unknown keys are preserved on ordinary edits. Opening defaults creates
  no file. Save As and draft handling keep options beside the relevant text.
  Changing options reinterprets the active editor and outline immediately.

* genericparagraph.h and CrumbModel own marker recognition, heading levels,
  provisional rows, counts and the outline. TitleOutline presents hierarchy
  or alphabetical results. guillemetmarkup.h pairs marks within one physical
  paragraph. guillemetediting.cpp implements Ctrl+K and exact wrap/unwrap.
  ManuscriptEditor reveals the literal signs at the caret, preserves the raw
  UTF-8 text in selections and saves, and keeps presentation out of undo.

* genericlist.cpp recognizes editable prefixes when starting a new paragraph.
  It preserves delimiters and case, advances decimal components separately,
  and distinguishes Roman sequences from alphabetic ones using neighboring
  items. Explicit Continue List (Ctrl+Shift+Enter) resolves an ambiguous
  first item. An empty generated prefix can be removed with Backspace or
  ended with Enter. Pasting and loading existing text preserve its numbering.
  wordselection.cpp supplies shared boundaries for mouse and keyboard word
  selection. In “notwithstanding—not” the em dash has its own selection.

* CrumbTitleLabel reserves two wrapped rows in the current-crumb panel.
  Enter on the focused label opens its full text. Navigation records new
  writing as it is created and updates the displayed title as typing proceeds.
  Generic mode puts its daily number immediately under the label. Crumb mode
  leaves room after the daily count. SynonymWriting blends the preview at
  30% normal foreground over the actual paragraph background. Genre names
  participate in spelling exemptions as complete phrases in Crumb mode.

* backupcomparison.cpp opens a read-only comparison of the active editor
  with its DocumentStore startup backup. Unique matching paragraphs anchor
  large passages. Short spans use an exact longest-common-subsequence match.
  A very large repetitive rewrite can appear as one changed passage. The
  before/after views read complete paragraphs. F3, Shift+F3, and F5 navigate
  and refresh. The comparison never writes to either manuscript or backup.
  Its two labeled columns participate in the shared layout manager. Settings
  travel with private recovery drafts, including checkpoints of failed named
  saves. Successful promotion or deliberate discard cleans up the private copy.
  The package smoke check decodes the actual bundled badge and reads its CC0
  dedication. Native packages also ship a separate human-readable notice.

* The BSD first artwork comes from github.com/AlfredoLlaquet/bsd-first.
  README.md uses the official SVG. The About dialog embeds an offline PNG
  derived from the official image against a light background. Its button
  supports Alt+B. The badge’s CC0 dedication is in data/bsd-first-LICENSE.
  packaging/release/assets.py names the seven versioned downloads. Changing
  a version requires updating the literal versioned links in README.md.
  tests/test-release-assets.py verifies those links, release-note filenames
  and checksums, including corresponding sources that span several files.
  A version-specific changelog in packaging/release/changes supplies the
  reader-facing release summary. The Krohnkite check opens a second window
  explicitly before measuring tiles; opening additional files exercises
  tabs in the same native window. The Windows and macOS install tests
  check OS window identity and frame through subsequent file-open events.
  The conflict-dialog audit discards its disposable changes explicitly before
  restoring the original file, exercising the same pending-save prompt as a writer.

For a change to a control or window, exercise its real keyboard and mouse
entry points, inspect a light and a dark capture on the affected native
platforms, correct defects and repeat the focused views. Shared controls
also require cross-platform checks. Version 3.0 introduced the tab strip, active
panel switching, the full crumb title, Manuscript Settings, the backup
comparison, About artwork and new markup views to this review. Exercise
resize and scrolling on a 25,092-crumb file, reload older hyphen manuscripts
and run the settings/backup tests before publishing.

Build, update and launch
------------------------

Crumb Writer is a C++17 and Qt 6 desktop editor for FreeBSD 15.x and 14.x,
Linux, Windows and macOS. Qt uses the available graphical platform. A single source tree handles
the manuscript, keyboard, search, spelling and windows on all four systems.
Qt Widgets provides the writing interface. Qt Network handles local activation.
The C parser and disk modules use GLib/GIO. GLib also provides the PCRE
search interface. FreeBSD's base C and C++ compilers and make build the
program. The qt6-base package supplies Qt Widgets, Qt Network and the rcc
tool that embeds the application icon. The Makefile locates them through
pkg-config, supplied by pkgconf.

Installing the FreeBSD and Linux release packages
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Use the package for the target OS, release series and architecture. Every
installer carries its version. The README links directly to the exact assets
under releases/download/v3.1/. Release checks exercise FreeBSD 15.1, 14.4,
and 14.5 (the latter two share one binary), Ubuntu 24.04 and 26.04, and
Debian 13. The install commands below assume a local download for amd64.

    FreeBSD 15.x   pkg install ./crumbwriter-3.1-FreeBSD-15-amd64.pkg
    FreeBSD 14.x   pkg install ./crumbwriter-3.1-FreeBSD-14-amd64.pkg
    Ubuntu 24.04   sudo apt install ./crumbwriter_3.1-ubuntu24.04_amd64.deb
    Ubuntu 26.04   sudo apt install ./crumbwriter_3.1-ubuntu26.04_amd64.deb
    Debian 13      sudo apt install ./crumbwriter_3.1-debian13_amd64.deb

On FreeBSD run pkg as root. For an update, close the editor, download the
new asset and repeat the install command with its filename. apt remove
crumbwriter or pkg delete crumbwriter removes the editor. Documents, backups
and companions remain in their original folders. See README.md for source
installation, expected compatibility, and the system launcher.

First installation on Windows and macOS
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

The README has a direct download link for each platform. The current
release, source, checksums and version-specific license are available at
https://github.com/AlfredoLlaquet/crumbwriter/releases/latest

Windows 10 version 1903 or later and Windows 11 use
CrumbWriter-3.1-Windows-x64-Setup.exe on x64 computers. Run Setup as the
desktop account. View License opens the notice during installation.
Start Crumb Writer from the Start menu or its optional desktop shortcut.
Setup can also add Crumb Writer to Explorer's Open With for plain-text
files while preserving the current default. Keep the manuscript and
companion files together in a personal folder.
To update, close Crumb Writer and run the new installer. To remove the
program, use Settings > Apps > Installed apps (Apps & features on Windows
10). Personal settings, manuscripts, backups and companion files survive
an update or uninstall.

macOS 15 or later uses CrumbWriter-3.1-macOS-Universal.dmg on both Apple
silicon and Intel. Open the disk image, drag Crumb Writer to Applications,
eject the image and open Crumb Writer from Applications. From the keyboard
in Finder, select Crumb Writer, press Command+C, press Command+Shift+A to
open Applications, then press Command+V. To update, quit the editor and
replace its application in Applications. To uninstall, move the app to Trash.
Personal manuscripts and their companion files live outside the app.

Verify a download
~~~~~~~~~~~~~~~~~

Every public installer has a signed GitHub build record (an artifact
attestation). In its download directory, a signed-in GitHub CLI can identify
the workflow and source revision that produced this exact file.

    gh attestation verify crumbwriter_3.1-ubuntu24.04_amd64.deb --repo AlfredoLlaquet/crumbwriter
    gh attestation verify crumbwriter-3.1-FreeBSD-15-amd64.pkg --repo AlfredoLlaquet/crumbwriter
    gh attestation verify CrumbWriter-3.1-Windows-x64-Setup.exe --repo AlfredoLlaquet/crumbwriter
    gh attestation verify CrumbWriter-3.1-macOS-Universal.dmg --repo AlfredoLlaquet/crumbwriter

Use the command for the file downloaded. For a SHA-256 check, compare
the output of the corresponding command with SHA256SUMS on the same release.

    Get-FileHash .\CrumbWriter-3.1-Windows-x64-Setup.exe -Algorithm SHA256
    shasum -a 256 CrumbWriter-3.1-macOS-Universal.dmg
    sha256sum crumbwriter_3.1-ubuntu24.04_amd64.deb
    sha256 -q crumbwriter-3.1-FreeBSD-15-amd64.pkg

The Windows installer has no Windows publisher certificate. SmartScreen
can display an unfamiliar-app or unknown-publisher warning. After verifying
the file, More info > Run anyway proceeds when allowed by local policy.
The Mac application is ad hoc signed and distributed without Apple
notarization. If Gatekeeper blocks the first launch of the verified app,
try opening it once, then go to System Settings > Privacy & Security and
choose Open Anyway for Crumb Writer. This is a per-app exception.

    Microsoft     https://learn.microsoft.com/windows/apps/package-and-deploy/smartscreen-reputation
    Apple         https://support.apple.com/en-us/102445
    Verification  https://cli.github.com/manual/gh_attestation_verify

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

On a FreeBSD 14.x or 15.x desktop, install the packages as root.

    pkg install git pkgconf glib qt6-base hunspell en-hunspell en-mythes poppler-utils

    git clone https://github.com/AlfredoLlaquet/crumbwriter.git

Opening a manuscript
~~~~~~~~~~~~~~~~~~~~

Ctrl+O opens a manuscript. Opening places the caret at the end of its text,
just before a final newline when present, with the preceding writing visible.
The default on the next launch is to restore the open windows and tabs. A
first launch and Ctrl+Shift+N open an untitled document. Opening a file that
is already open raises its existing window at its current writing position.
An optional filename argument activates that manuscript after session restoration. Several filenames open tabs in the active window.

Mode and manuscript structure
-----------------------------

The right end of the status bar shows Crumb mode or Generic mode. The mode is
derived from the current first physical line. A literal // outside a URL
marks Crumb mode. Embedded slashes in a web address, such as the pair in
https://www.thecrumbs.org/, belong to the address. Any other first line,
including an empty line, selects Generic mode. Inserting, removing or undoing
the first-line delimiter changes the mode immediately. Saving in either mode
writes UTF-8 without a byte order mark (BOM). src/storage.c accepts a leading
BOM on input and omits it from saved text. A startup backup preserves the
original bytes. Fonts, wrapping and navigation aids are display choices. A
saved manuscript contains its text and physical line endings.

Writing crumbs
~~~~~~~~~~~~~~

In Crumb mode every physical line holds one piece. On line 1, the title of
the entire work is immediately followed by // and the first crumb. No spaces
are needed around //. Choose a distinct header label for each collection.
The example fits on one physical line.

    Cranolos - Manolo’s Crumbs//Cranolo 1: The Inspector: A goose audits the moon for bumps.

The header "Cranolo 1" combines the label, a space and a positive decimal
sequence number. The first colon ends the header. "The Inspector" is the
title of the piece. The second colon ends the title. All remaining text is
the body, including its punctuation, additional colons, verse separators,
URLs or inline-footnotes inside ‹{ }›. Either title or body may be empty.
An unfinished line stays editable. Crumb 1 occupies file line 1, and the
line number increases with each piece. A title such as "Night Audit #2"
carries a separate number for one recurring genre.

A fresh installation selects 14-point Georgia on Windows, Charter on macOS,
or Noto Serif on BSD and Linux, falling back to the available serif family. Headers are
italic, titles bold and bodies normal. The full editor width is available.
An ordinary resize, tiling, or moving the sidebar divider rewraps prose.
There is a gap of about a quarter of a text line between physical crumbs.
Wrapped rows within the same crumb keep normal line spacing. Scrolling and
jumps take effect immediately.

The official website offers a real example of publishing this format. Its
Reader loads Crumbs.txt and validates its Crumb headers against file line
numbers. For line 1, the parser extracts the title "The Game" and its body.
The page links directly to that individual piece and supports browsing,
search and favorites. The README gives a second worked example using the
Cranolo label above.

    Published manuscript   https://github.com/AlfredoLlaquet/Alfredo_Llaquet-Alsina_Crumbs/blob/main/Crumbs.txt#L1
    Reader parser          https://github.com/AlfredoLlaquet/Alfredo_Llaquet-Alsina_Crumbs/blob/main/Reader/core.js
    Read The Game          https://www.thecrumbs.org/Reader/?crumb=1

Writing novels and other prose in Generic mode
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

The writer types consecutive prose paragraphs on consecutive file lines.
The editor wraps each line to the available width. These six file lines
form the worked example in the reader guide.

    The Harbor of Borrowed Tides

    The Night Clerk
    ---------------
    At dusk the harbor clerk signed for a tide that had arrived in six wooden crates.
    By dawn the water had learned the shape of the pier.

The first nonblank paragraph on file line one becomes the general title if
it has no ASCII period, if all its cased letters are uppercase, or if its
next line is blank or is a confirmed heading marker. The per-manuscript
option Disable general title detection lets line one open directly with prose.
An explicit marker can then give that paragraph an ordinary heading level.

GenericParagraph recognizes a row of matching ASCII characters starting in
column one. The characters =, -, ~ and . mean levels 1 through 4. One mark
suffices. A new marker stays provisional while the writer is on its row,
including during background saves. A following space permits a list item
or prose to develop. When the caret leaves an otherwise marker-only row,
the editor confirms it. DocumentStore normalizes a confirmed marker to the
number of visible graphemes in its heading, including spaces; guillemet
markup follows the manuscript's literal setting. Existing hyphen headings
naturally enter level two. Each marker belongs to text immediately above.

The general title uses the largest bold face. The four section levels have
vertical spacing and descending sizes. In markup view levels 1 and 2 use
solid underlines and levels 3 and 4 use dotted ones. Level 4 uses body-sized
bold type. Ctrl+Shift+F9 reveals the marker characters and underlines.
The first blank directly after a
general title may be compact. Other interior blanks retain their height.
Ctrl+Shift+4 opens the Titles search. Document order shows an outline,
alphabetical order disambiguates repeated names using their ancestors, and
the general title opens at the top of the viewport. The active heading
follows typing or navigation without taking keyboard focus.

A publishing script can map the book title to h1, chapters to h2, and each
ordinary line to a paragraph in HTML. In the example grep -nF 'six wooden
crates' Harbor.txt identifies the entire paragraph on the fifth file line. The
README explains how the same source supports revision and ebook or print
publication.

Ctrl+Shift+4 searches Titles, listing the general title and the chapters
in document order by default. Shift+F7 switches to alphabetical order.
The choice for Titles is independent of the genre sort preference. Enter
jumps to the highlighted heading. End of document stays last in either order
and moves to the end of the last real paragraph, skipping trailing markers,
blank lines and virtual space. Ctrl+Shift+3 searches the full text of
visited paragraphs while displaying their openings. Blank separators and
unaccepted movement previews do not enter visit history. Ctrl+Shift+I opens
live statistics for nonblank paragraphs and their total and average words.

Word counts, statistics and daily totals
----------------------------------------

For an individual crumb, count the header, title and body. On line 1, omit
the work title and its // delimiter. Count runs separated by whitespace.
An em dash separates adjacent words. A slash with one ordinary space on each
side counts as a separator. An attached hyphen or apostrophe stays part of
its word. A standalone punctuation token still counts, so "Crumb 2: :" has
three words. In the example above, "Cranolo 1: The Inspector: A goose audits
the moon for bumps." has 11 words. Its full physical line has 15 because the
work title contributes four (including the freestanding hyphen).

The official whole-file count includes the work title. Use this command
in the host locale on FreeBSD, Linux or macOS.

    sed -e '1s@//@ @' -e 's/—/ /g' -e 's@ / @ @g' Crumbs.txt | wc -w

The first substitution replaces the first // on physical line 1 with a
space. The remaining substitutions operate on all lines, converting each
em dash and each nonoverlapping literal " / " to spaces. wc -w counts the
result. For an individual first crumb, strip its actual work-title prefix
before applying only the last two substitutions. Generic mode applies the
whitespace, em dash and spaced slash rules directly to the prose and
counts URL slashes as part of their token.

After sed makes those replacements, FreeBSD and Apple wc -w classify
individual unsigned bytes with the native locale. Their wc decodes whole
multibyte characters when -m is supplied. GNU wc on Ubuntu reads whole
characters in a UTF-8 locale.

Windows reproduces FreeBSD 15's wc -w in C.UTF-8 without invoking a
shell. In this byte range the separator values are ASCII whitespace and
0xA0. For example, a narrow nonbreaking space (U+202F, bytes E2 80 AF)
between two letters leaves one word. A word joiner (U+2060, E2 81 A0)
between the same letters splits them into two words because of its last
byte. The Windows display language has no effect on these rules.

Ctrl+Shift+I opens modeless Manuscript Statistics. In Crumb mode, Crumbs
counts recognized records. Total words includes the first-line work title
and words on unfinished lines. In Generic mode, Paragraphs counts nonblank
physical prose lines, including recognized headings. Markers and blank lines supply no
words or paragraphs to the average. In either mode, the average divides the
whole-manuscript total by the indicated count and displays two decimal places.
An empty manuscript shows zero. Figures share a right-aligned column with
padding, locale-specific number separators and US English formatting for
the C locale. Four-digit totals always show grouping. Ctrl+C or Copy copies
all three figures with their labels.

In Crumb mode, New today counts the new recognized crumbs still present on
the local calendar date. Add three and delete one of them to leave two.
Undo restores the third. Deleting a crumb from an earlier day leaves the
count intact. In Generic mode, the compact top right panel shows only
"New words written today" and a grouped, signed net word count. It measures
the change from the day's starting word total. Deleting more words than
were added can give a negative result. Undo and redo affect it.

These counters persist per manuscript across sessions. Midnight begins a
new local day even if the editor stays open. The per-manuscript data live
under crumbwriter/daily in the account's Qt data directory. On FreeBSD
and Linux this is $XDG_DATA_HOME/crumbwriter/daily, which normally resolves
to ~/.local/share/crumbwriter/daily. On reopening a manuscript the editor
closes the saved count file before replacing it, so Windows can restore a
checkpoint or start a new day without a file-sharing error.
The daily state preserves the crumb identities and word-count baseline
needed to recover the appropriate totals, including after discarded edits.
A successful manuscript or recovery-draft save checkpoints the saved revision.

Appearance and editing
----------------------

The active crumb or paragraph uses a faint tint of the desktop accent on
all its wrapped lines in both light and dark themes. When the main
window loses focus, the whole manuscript takes a softer gray and the band
disappears. Dark paper keeps light text. Focus in a side panel, Find, or
Replace belongs to the main window. Selections, search matches, warnings,
spelling marks, and synonym hints use colors appropriate to the chosen
palette. Settings offers Follow desktop, Light, Dark, and a manuscript font
from 6 to 96 points.

F10 opens File in the menu bar. The toolbar carries Open, New, Save, Find,
Font, writing size and Style. Three-line buttons beside Characters and
Recurring open those lists' options. From a list search field, Shift+Tab
focuses its menu button. Space, Enter or Down opens the focused button.
Escape closes its menu.

Explicit Light or Dark applies to the complete application, including
popups, the About link, file and color pickers, and confirmations. On
Windows and macOS these choices use Qt's Fusion controls so the style
paints the background and foreground together. Follow desktop restores
the desktop style and system dialogs. FreeBSD and Linux keep their
desktop widget style. Opening another manuscript clears the previous
file's notice before displaying any warning about the newly opened file.
The close and confirmation buttons in an explicit theme use their text
labels. Confirmation dialogs display the full question and its choices.
Follow desktop honors the desktop's standard button and dialog icons.
The built-in Open and Save As dialogs use the active theme's ink for
Back, Forward, Parent Directory, New Folder, List View, and Details.
When both KDE Breeze icon sets are installed, an explicit appearance
uses its matching set for folder and file-type icons. A selected filename
keeps its highlight while its icon is drawn on the list's normal background.
Search fields in both sidebars, Bookmarks, and Insert Symbol show a clear
button when they contain text. Clearing a field keeps the keyboard there.
The manuscript font applies to the writing area. Context
menus, spelling suggestions and the name list keep the interface font,
including when the manuscript is set to 96 points.

In Crumb mode, Ctrl+N uses the last recognizable label and one greater
than the largest valid header number. With no earlier label it uses Crumb.
An empty title produces "Crumb 42: : " with the caret after the final space.
In a blank window, typing the work title and // switches to Crumb mode.
Ctrl+N then creates the first header on that same line. Change Crumb to a
particular label once and the next header reuses it. Existing terminal line
breaks follow the newly appended crumb. One Undo removes the new record and
restores the exact original selection, caret, and view. Redo returns to
the newly appended body or paragraph. The Genres action uses the same edit.

Typing "Haiku #" in a title completes the next number from the nearest
earlier Haiku. The typed genre spelling is preserved. With no previous
occurrence, the hash remains available for writing. A hash in a body is
literal. The Genres list shows the most recent number of each genre. The
button beside Genres, or Shift+F7, switches between alphabetical order and
increasing last number, with ties sorted by name. The choice is remembered.
Activating "Portrait #42" appends a new crumb titled "Portrait #43"
and focuses the body. Ctrl+Shift+4, a fragment of the genre name, and
Enter do the same from the keyboard. A title such as "Negation #10, Confession #3" indexes
both components. "Fingers (Haiku #157)" also contributes to Haiku.

Bold red digits flag a header whose number differs from its one-based
physical line, or a numbered genre that breaks its sequence. The first
occurrence of each genre expects 1. Subsequent occurrences use the previous
written ordinal plus one. In Haiku #1, #3, #4 the 3 is flagged and the 4
follows normally. Blank or unfinished physical lines count toward header
line numbers. F4 and Shift+F4 visit the next or previous warning, select
the digits and show the expected and actual values. Saving preserves the
written numbers.

Tabs and runs of ordinary spaces become a single ASCII space. Pasting
normalizes the whole insertion and its edges in one undoable edit. Newlines,
blank lines and nonbreaking spaces are preserved. A space typed at the end of
a crumb stays available for the next word, including across a live save.
Backspacing over the last word also leaves its preceding space available.
Leaving the crumb or beginning a search trims a pending trailing space. Saved
manuscripts, drafts and copied crumbs omit trailing ASCII spaces and tabs.

Smart punctuation operates on typed keys and committed input-method text.
A following character supplies context for straight quotation marks and
apostrophes. Typing the t in Don't produces Don’t. Typing a space after
Pepe," produces Pepe,” and the space. Typing the s in new--s produces new—s.
Three periods become … when the sequence is resolved. Moving the caret,
leaving the editor, an explicit save, or closing the document resolves
pending punctuation. A paste or search replacement keeps its literal
punctuation. Settings can disable smart punctuation. Curly punctuation
belongs to the saved UTF-8 text.

Ctrl+Z undoes a continuous run of typing, including spaces, pauses, smart
punctuation and completed input-method text. Consecutive Backspaces form
one step, and consecutive forward Deletes form another. Switching operation,
moving the caret, entering a line break, pasting, or explicitly saving ends
the typing run. An automatic save may publish part of a run while typing
continues. Undo still covers the complete run. Ctrl+Shift+Z replays the
same edits, including typographic characters and genre-number completion.

Settings → Writing → Copy deleted text to the clipboard defaults to off.
Read an existing editor/copy-deleted preference as stored. Cut always
writes to the clipboard. Plain Backspace or Delete with no selected text
never writes to it, even on autorepeat. Those edits still coalesce for
undo. With the option enabled, erasing an explicit selection, word, or
entire crumb copies the removed passage. Pasting over a selection reads
the incoming text before copying the displaced text. Replace All and
bulk spelling corrections copy the actual displaced passages in manuscript
order separated by LF. Automatic punctuation, normalization and replaying
undo or redo preserve the clipboard.

Visits are ordered most recent first. The list shows only titles in Crumb
mode (Untitled for an empty title), or the opening text of paragraphs in
Generic mode. Each visit carries its own caret position, so identical titles
can lead to different passages. Click an entry or press Ctrl+Shift+3, type
a fragment, and press Enter. Escape returns focus to the manuscript. F2
and Shift+F2 move back and forward among deliberate jumps. Alt+Left and
Alt+Right do the same. Refining a search keeps its original return position.
Ctrl+Shift+J and Ctrl+click first open any URL under the caret or pointer,
then look for a numbered crumb reference and finally for a previous mention
of a name or crumb genre. Both "crumb 200" and
"see Cranolo 200" work in a manuscript whose label is Cranolo. Numbered
references take precedence over names. A mouse jump searches from the clicked word,
and Back returns to the writer's caret before the click.

Live movement selections
------------------------

In the manuscript, press Ctrl+Space. The current caret becomes the fixed
origin. The bottom bar shows the typed command. Each keystroke, paste or
Backspace recomputes the selection from that same origin. Append the count
to the movement: j selects into the next physical line, j2 into the second,
and removing the 2 restores the first preview. Press Enter to accept and
leave the text selected. Escape restores the opening caret, selection and
scroll position. Incomplete input or a missing match displays the original
selection and keeps the command available for correction. Only an accepted
movement can register a visit.

    h / l           Left / right one character, including across physical lines
    j / k           Next / previous physical line at the same character column
    gj / gk         Next / previous wrapped screen row at the same horizontal position
    w / b / e       Next word's start / a word's start backward / through its end
    W / B / E       The same, using whole runs of non-whitespace as words
    0 / ^ / $       Physical line start / first nonblank / physical line end
    gg / G          First / last physical line, at its first nonblank
    G42 or gg42     Physical manuscript line 42, at its first nonblank
    fX / FX         Forward / backward through character X, including it
    tX / TX         Forward / backward up to X, leaving it outside the selection
    ; / ,           Repeat the last accepted f/F/t/T in its original / opposite direction
    qtext / Qtext   Forward / backward through the whole literal text, ignoring case

Character searches respect case and can cross paragraph or crumb boundaries.
Type t-2 to select up to the second hyphen to the right. In "red-fox
fled-quickly" with the caret before red, the result is "red-fox fled". An f,
F, t or T takes its first character as the target even when it is a digit.
For example, f23 finds the third 2. Counts following ordinary movements are positive.

In q/Q a phrase can contain digits or spaces. Use an asterisk to introduce
a repeat count. Type qt to preview the next t, add h for the next th, then
add *2 for the second th. Qth*2 finds the second preceding th. In either
direction the selection includes all of the matched phrase. Type \* for a
literal asterisk and \\ for a literal backslash. "qfee\*2" searches for the
literal text "fee*2". Ctrl+V can supply a phrase with actual line breaks.
Character and phrase searches stop at the corresponding manuscript boundary.
Enter finishes every movement, including a one-character command.

A four-row paragraph occupies one physical line. From its second screen
row, gj selects down to its third. From the same starting point, j selects
into the next paragraph. Movements use the nearest available column on a
shorter destination. Combining marks and emoji stay with their character
during horizontal movement.

Search and replacement
----------------------

Ctrl+F opens forward Find from the manuscript caret. Ctrl+G opens backward
Find from the same position. Ctrl+P starts a forward plain-text search and
Ctrl+R starts a forward regex search directly from the manuscript. In a
search field these keys switch the mode of the current search. Plain-text
input immediately selects the nearest
match in the opening direction and centers its starting visual line. Each
refinement starts at the original search caret. Clearing the query or
refining it to a missing match after a preview returns to the origin. Escape
closes the panel, clears the selection and returns focus to the manuscript.

Ctrl+H opens Find and Replace. Further Ctrl+H switches keyboard focus between
Find and Replace with, keeping both values. Ctrl+L opens direct number
navigation. Enter a positive number and press Enter. In Crumb mode the
number index finds matching headers and handles alternate labels, duplicate
numbers, direction and wrap. In Generic mode a number selects the physical
line, including a blank separator. Replacement is available in plain-text and regex modes.

    Ctrl+P / Ctrl+R / Ctrl+L   Plain text / regular expression / header or line number
    Ctrl+M / Ctrl+W / Alt+W    Toggle match case / whole words / wrap
    Alt+Down                  Show recent searches and focus the list
    Enter / Shift+Enter       From query, repeat forward or back relative
                              to the opening direction
    F3 / Shift+F3             Repeat in the opening / opposite direction

F3 and Shift+F3 also work with the panel closed. After Ctrl+G, F3 goes
backward. After opening forward Find or Replace, F3 goes forward. While the
Find controls have focus, Ctrl+W toggles whole words and Alt+W toggles wrap.
With the manuscript focused, Ctrl+W deletes and Alt+W closes the window.
Ctrl+N appends a crumb or starts a paragraph even from the Find field.
Escape closes the search bar from the search controls or the manuscript.
Completed queries retain their mode and options in recent searches. Arrows
and Enter recall a search. Repeating an identical query and options moves
that entry to the top. The Qt version reads existing 1.4 search history.

Text and regex start case-insensitive, with wrapping at file ends. Regular
expressions use GLib's PCRE syntax with multiline anchors and ungreedy
repetition. A dot matches a single character except a newline by default.
The following expressions can be typed directly in the Find field.

    Haiku #[0-9]+:         A numbered Haiku title through its colon
    “.*”                   A single curly-quoted passage on one line
    (?-U)“.*”              Through the last closing quote on that line
    ‹\{.*\}›               An inline-footnote with its literal braces
    ^Crumb ([0-9]+):       Capture a number in a header at the start of a line

In Crumb mode the work-title prefix precedes the header on line 1. In regex
replacement text, \1 inserts the first capture. Plain-text replacement
treats its replacement literally. All… displays the number of replacements,
the number of affected lines, and up to four before-and-after examples.
Apply all executes the preview as a single undoable edit. Changes to the
manuscript, query or replacement invalidate the preview.

    PCRE2 syntax       https://www.pcre.org/current/doc/html/pcre2syntax.html
    PCRE2 patterns     https://www.pcre.org/current/doc/html/pcre2pattern.html
    Replacement text   https://docs.gtk.org/glib/method.MatchInfo.expand_references.html

Characters and Recurring
------------------------

The left panel has two alphabetical lists. Ctrl+Shift+1 focuses Search
Characters and Ctrl+Shift+2 focuses Search Recurring. Typing part of any
alias highlights the first case-insensitive match. All rows stay visible.
Up/Down cycle through the matches, wrapping at the ends. From the field or
list, Enter finds every occurrence of all aliases in the selected group.
Ctrl+Enter inserts its first synonym. Either action clears the search field.
Escape returns focus to the manuscript.
Insert opens Add with the selected manuscript text suggested as one alias.
On macOS, physical Control+I does the same in either the Characters or
Recurring search field or list. On a compact Mac keyboard, Backspace (often
labeled Delete) removes the selection in a focused synonym, bookmark, or
manuscript dictionary list. In a search or edit field it edits the text.
The field selects the suggestion so typing can replace it. Commas and quotes
are escaped using the companion-file syntax. Physical line breaks become
spaces and surrounding whitespace is trimmed. An empty selection opens a
blank field. Enter saves and Escape cancels. F2 edits the selected group
and Delete confirms removal. Open a search result to select its text in
the manuscript. F2 in the manuscript returns to the place where that jump
began. Shift+F9 shows or hides the entire left panel.

The right panel follows the same search rules. Ctrl+Shift+3 searches visit
history. Ctrl+Shift+4 searches Genres or Titles. Enter activates the current result. A visit or title jumps to its passage;
a genre appends its next crumb. In Genres Ctrl+Enter finds all occurrences.

A manuscript named Crumbs.txt has two UTF-8 text companions named
Crumbs.txt.characters and Crumbs.txt.recurring. Each physical line is one
group. The first synonym determines the display order and insertion text.
The optional leading metadata fields ,no-complete, exclude this group from
automatic and F5 completion. The group editor exposes this as Exclude from
autocomplete (Alt+E), initially unchecked. Legacy rows retain their behavior.
Underlining, occurrences, spell exemptions and explicit insertion continue.
Separate aliases with commas. Spaces around separators are ignored. Put an
alias containing a comma in double quotes. Double a literal straight quote
inside a quoted alias. For example, this line has three aliases.

    "Fox, Captain", Red Fox, Captain Fox

Matching is case-insensitive and literal. A search for Fox finds the name
as a word. F5 reloads changes made to the list file in another editor.
Save As copies the lists alongside the new manuscript.

In Settings → Names each list offers Automatic, On demand, or Off for
completion. The default minimum is three typed characters for an automatic
suggestion. A unique match shows a faint ending. F5 accepts that ending
as one undoable edit. If the ending would cover existing text or run off
the page, the status bar shows it instead. F5 works from one typed character
for on-demand lookup. F5 also opens a keyboard chooser when several names
match. Arrows and Enter choose, Escape dismisses. Ordinary typing uses
the alias the writer started, including multiword names.

Each list offers All mentions, Current group only, or Off for its thin
straight underline. A blank underline color follows the desktop or selected
theme. Recognition uses complete names with Unicode word boundaries and
treats straight and curly apostrophes as equivalent. A shorter alias
contained in a longer mention contributes no extra hit. In "Inspector
Goose saluted a goose", Inspector Goose and the second goose are two hits.

The matcher also indexes the current Crumb manuscript's genre names as
navigation terms. It drops them when the mode or source changes. Genres
use Recurring's underline preference and never supply a completion by
themselves. Longer overlapping matches suppress shorter matches; the
exact visible match in each occurrence excerpt is bold. Replace All uses
the matched source spans for its before previews.

F6 finds an earlier mention of any alias in the group under or immediately
before the caret. Shift+F6 looks forward. Ctrl+Shift+click follows a name
forward. macOS accepts Command+click and Command+Shift+click as well.
An alias belonging to several groups offers a keyboard chooser. A successful
jump centers its destination and records the departure in Back/Forward.
Reaching the first or last mention shows a brief message and leaves the
writer in place. Completion and underlining settings are independent of
navigation and of F3 manuscript search.

Word tools, web addresses and status
------------------------------------

Ctrl+2 selects a word including internal hyphens and apostrophes without
copying it. F7 opens the modeless Offline English Thesaurus against the
selected phrase or the word under the caret. The list groups alternatives
by sense. Arrows choose, Ctrl+C copies, Enter replaces the bookmarked
source span in one undoable edit, Ctrl+L focuses the lookup, and Escape
closes. WordTools closes its dialog on a manuscript change to protect the
captured range. The three Merriam-Webster commands share a two-key prefix:
Ctrl+Shift+L then D (dictionary), S (dictionary entry #synonyms), or T
(thesaurus). Escape cancels. Each sends only the selected term as an
encoded path component to the default browser. Local F7 stays offline.

http://, https:// and www. addresses are recognized across both modes.
Keep balanced parentheses/brackets; trim unrelated sentence punctuation.
The actual hit range has priority over local references and names. Open
with Ctrl+click, Command+click on macOS, Ctrl+Shift+J, or the editor's
Open Link context command. Spell checking skips the complete range in
underlines, review and bulk correction. Treat a singular possessive 's
or ’s as a suffix when checking a saved stem (Hedberg covers Hedberg’s).
Keep intact contractions and internal apostrophes such as I’m and O’Brien.

The center of the footer opens https://www.thecrumbs.org/ in the default
browser. Its text uses the ordinary foreground in both palettes. The left
writing status and right mode take priority at narrow widths or during
a movement or lookup command. Change footer layout only when the link
actually needs to appear or disappear. Help > Open TheCrumbs.org also activates it.
Tools > Set Today’s Count opens a modeless signed-integer editor. Reset to
Zero fills the field; Enter applies the chosen value. Generic words can
be negative. Crumb totals have zero as their lower bound. Keep adjustments
separate by local date, manuscript and mode and apply later edit deltas.
Persist explicit corrections to the current committed or recovery state
even when text is untouched; an older autosave must not roll one back.

American English spelling
-------------------------

Spelling uses Hunspell with en_US and is enabled by default. In Generic
mode, the checker also reviews prose that resembles a numbered crumb header.
Ctrl+, opens Settings, where Check American English spelling switches it on
or off.
Underlined words can be reviewed from the keyboard with F8 and Shift+F8.
The correction dialog offers suggestions, an editable replacement, Replace,
Replace All, Ignore Once, Ignore All and Add to Dictionary. The manuscript
context menu also provides corrections. In the replacement field, Enter
applies the correction. Alt+A replaces all, Alt+I ignores once, Alt+L
ignores all, and Alt+D adds the word to the manuscript dictionary.
Ctrl+Shift+D opens that dictionary. Type to filter or press Enter to add
the typed word. Delete removes the selected entry and F5 reloads from disk.

Straight and curly apostrophes are equivalent for spelling, including in
contractions such as don't and don’t. Both synonym lists exempt complete
aliases. Listing Zorbo Marmalade exempts that full name. Adding Zorbo as
another alias or as a dictionary word accepts it on its own. The personal
dictionary for Crumbs.txt is Crumbs.txt.dictionary, a UTF-8 file with one
entry per line. Entries match regardless of case. Save As carries this file
alongside the copied manuscript.

Named bookmarks
---------------

Ctrl+B bookmarks the current physical line. Each bookmark has a category and
a name. The default category on first use is General. The next add remembers
the previous category, so Ctrl+B followed by Enter adds its next numbered
bookmark. A category starts numbering at 1. A manually assigned positive
decimal name such as 7 can advance its counter. Deleting a numbered bookmark
preserves the category's counter. Names are unique inside a category.
The wider Add Bookmark dialog gives the category field room to show long
names and can shrink when the desktop tiles the window.

Alt+B opens a separate modeless Bookmarks window for that manuscript. Tree
view presents categories and names. A category with one bookmark opens that
line directly. List view displays category, name, physical line and the
current crumb title or paragraph opening. Filter matches category, name,
line and displayed text, ignoring case. Separate words can match different
columns. Enter opens the selected bookmark and returns to the editor.

Bookmarks follow text through editing. If a line is inserted above a
bookmark for line 200, it moves to line 201. Delete the target itself and
the next surviving physical line inherits the bookmark. If there is no
next line, the last surviving line inherits it. In an empty document the
destination is line 1. Undo reinstates the old target. Redo follows the
edit again. The final newline's insertion position is outside the set of
bookmarkable lines when a preceding physical line exists.

Inside Bookmarks, Ctrl+F focuses Filter. The arrow keys reach the results.
F2 on a result edits its name or category, Delete asks before removing the
selection, and F5 reloads the companion file. In the manuscript window, F2
continues to mean Back.

A manuscript named Crumbs.txt uses Crumbs.txt.bookmarks in the same
directory. The companion is indented UTF-8 JSON. Version 2 retains
lastCategory, the persistent counters and the bookmarks array. Each entry
contains category, name and the one-based line. Its context object stores
a target fingerprint and, when those lines exist, before and after
fingerprints. These are SHA-256 hashes of the exact lines in UTF-8.
The display label is read from the current manuscript. It changes with the
passage and is independent of the bookmark name.

Version-1 files open automatically. A bookmark initially uses its saved
line number, clamped to the available physical lines. Opening upgrades the
companion with the new format and context. When an outside editor changes
the manuscript while it is closed, the next open looks for the recorded target. Neighboring lines
help choose between identical candidates. The closest match to the saved
position wins a tie, then the earliest in file order. If the target is gone,
the neighbors identify its replacement or successor where possible.
If all traces have gone, the saved line is clamped to the current file.

Bookmark edits to a named file use a lock, compare the disk bytes and publish
atomically. A manuscript save captures the bookmark positions for that exact
revision. If typing moves a bookmark during the write, its newer position
is kept for the next save. An untitled manuscript keeps pending bookmarks in
memory. Save As carries bookmarks beside the new manuscript. A conflicting destination
companion triggers a notice and leaves the copy pending for recovery or
retry. Reload rereads changes made to the companion by another editor.

Saving, closing and recovery
----------------------------

By default an existing manuscript receives a private backup in its own
directory before editing. The backup preserves the original bytes, including
a BOM, mixed line endings and original whitespace. Each opening gets a
unique filename, for example Crumbs.txt.YYYYMMDD-HHMMSS-xxxxxxxx.bak.

Manuscripts and drafts are written as UTF-8 without a BOM. Invalid UTF-8
and embedded NUL bytes are reported at open. File loading accepts LF, CRLF
or CR and exposes LF to the editor. A saved nonempty manuscript ends with one logical line terminator using the
existing line-ending convention. Remove trailing blank/whitespace-only rows
in both modes. An empty manuscript writes zero bytes. On opening an existing file, discard
surplus trailing empty rows before positioning the caret. The startup backup
still contains the original bytes. A bookmarked marker retains its physical
line when its hyphen count expands and its neighboring context agrees. The
daily header identity checkpoint ignores terminal empty rows. Older shapes
can be compared against the original opened layout so duplicate crumb header
numbers retain their distinct identities. Canonicalization of
the saved snapshot preserves an active editing position and open undo run. The storage layer preserves mixed endings
when matching existing lines. It also keeps adjacent CR and LF separators
distinct when an intervening whitespace-only line is cleaned. Ctrl+S can
strip an input signature and normalize spacing even on an untouched document.

Live saving defaults to one second from the first outstanding edit. Settings
can choose a delay from 1 to 30 seconds or manual saving. The GUI captures the
current text once per write. A worker per document performs UTF-8 encoding,
spacing cleanup, external-change verification and disk I/O. The editor can
accept new typing during this work. Each completed write acknowledges only
the revision that was actually saved. Later edits remain pending.

Before replacing a file, the writer checks its identity and exact disk bytes,
writes and synchronizes a temporary sibling, then publishes the replacement.
New destinations use exclusive creation. Existing local symlink targets are
resolved on open. A failing or externally changed manuscript displays a
notice and keeps the working copy. Ctrl+S retries, and Ctrl+Shift+S saves it
under a new name. A failing manuscript write attempts a private recovery
draft. With live saving enabled, untitled documents also receive drafts in
the account's GLib data directory under crumbwriter/drafts. On FreeBSD and
Linux this is $XDG_DATA_HOME/crumbwriter/drafts or ~/.local/share/crumbwriter/drafts.
Recovery drafts reopen as unsaved manuscripts at the next launch.

FreeBSD can finish updating an inode's change time after a successful
rename. If only that time changes during a save, the editor verifies the
file's exact bytes on the open descriptor, then checks the pathname again
before publishing. A replacement inode, edited bytes, or changed write
permissions still stop the save. This applies to the next save after Save As
over an existing file as well as subsequent live saves.

On Windows, native wide-character paths preserve names in every script.
The disk layer verifies the original file identity and bytes again under
a file lock, flushes the temporary file and replaces the target using
Windows file APIs. Backup creation never overwrites an earlier backup.

Closing with queued edits, an active write, a save failure or pending companion files
opens the Unsaved Changes dialog. A fully saved document closes directly.

    Save and Close          Save the latest edits, then close on success.
                            An untitled manuscript opens Save As.
    Discard Unsaved Changes Drop pending edits and remove the recovery draft.
                            Previously committed edits remain on disk.
    Keep Editing            Return to the manuscript. Escape chooses this.

The close confirmation pauses automatic saves. Discard can cancel a write
before the atomic publish point. A prior live save, or an in-flight write
already past that point, is already on disk. The startup backup retains the
pre-session bytes. A failed Save and Close keeps the window available.

Implementation and maintenance
------------------------------

The default make target builds the Qt application. Each physical manuscript
line maps to one QTextBlock. Qt cursor offsets use UTF-16 code units, disk
operations use UTF-8 bytes and the C parser counts Unicode code points.
Convert at the model boundary. The plain-text snapshot preserves nonbreaking
spaces and converts document paragraph boundaries to LF. Only the disk layer
reintroduces physical line endings. Formatting and search highlights stay
outside the manuscript text.

The manuscripttext adapter preserves literal U+2029, U+FDD0 and U+FDD1,
which Qt uses internally for document structure. Reading spans through this
adapter keeps file bytes, clipboard text and search positions consistent.

The first spelling request loads the US dictionary on a background thread.
The Windows and macOS installers supply SCOWL's US English dictionary in
dictionaries/en_US.aff and en_US.dic, next to the executable on Windows and
under Contents/Resources on macOS. These bundled files take precedence over
other dictionaries. Unix installations use the dictionary package supplied
by the operating system.
The build passes -pthread to the C++ compiler and linker so FreeBSD can
start that thread. All editor windows share the loaded dictionary.

Each manuscript has one QPlainTextEdit with a QSyntaxHighlighter. It follows
the widget width. A Qt plain-text layout computes visible paragraphs at the
current width. The background band is painted over visible wrapped rows. In Generic mode
the layout uses a small default font for empty separators, with body and
heading sizes applied to the appropriate nonblank blocks.
Whole-file regex scans and replacement planning can run in the background.
Stale results are invalidated when the query or document changes.

Characters and Recurring feed a shared case-folded prefix tree. Matching
caches offsets within individual text blocks. Editing a paragraph invalidates
that paragraph. Moving or wrapping a block at a new width can reuse its
relative matches. The Occurrences window processes blocks in short batches
and uses the same matches as underlining and navigation.

Every typed or deleted character completes its own QTextCursor edit block
so model observers, painting and autosave can see the new text immediately.
The next uninterrupted operation of the same kind uses joinPreviousEditBlock
to group native undo commands. Smart punctuation and genre completion occur
inside the same transaction. Autosave reads a snapshot independently.

Shift navigation calculates the same destinations as ordinary Ctrl navigation
and retains QTextCursor's anchor. Vi commands start at the active caret and
recompute each candidate from the same opening position. Enter accepts the
result. Escape restores the prior selection and scroll position. Physical
line motion counts graphemes. Wrapped-row motion uses the current QTextLayout
and horizontal pixel position. Literal character and phrase finds scan only
the blocks they visit. A query containing an actual newline uses the full
manuscript snapshot. An incomplete command never edits the document.

On the Linux/X11 test machine, Xfwm tiled the complete editor from
1050 x 680 to 672 x 990 with the last of 3,371 crumbs on screen. In two
unedited trials, version 2.0 drew the resized manuscript in 18.48 ms and
14.69 ms. The process used 0.02 and 0.03 CPU seconds across the respective
observation windows of 2.15 seconds. In version 1.4 the same window resize
used 1.83-1.90 CPU seconds. Ten characters typed during a separate tile reached
the last crumb on disk through normal live saving. These are Linux software
paint measurements. The resize test also runs natively on FreeBSD and
prints its own results for 3,371 and 25,092 synthetic crumbs.

The model uses each edited range from QTextDocument. A same-line change
reparses that line, and a genre edit revisits affected successor warnings.
A change to physical line numbering reuses the parsed records for unaffected
text. Header lookups use duplicate-aware sorted positions, and genre
completion finds the nearest earlier occurrence. In Generic mode, physical
the next ASCII marker line sets the heading level. The first line also uses the
general-title rules, including an immediately following blank. An ordinary edit can
change the role of an adjacent paragraph. Changing the first-line mode
reclassifies the manuscript and updates the outline, statistics, status bar,
search labels, and editor formatting. Each manuscript session owns its mode.

Visit and jump history follow live cursor positions. BookmarkAnchors adds
undo destinations and a persistent line reference to each named bookmark.
Opening an unchanged manuscript reads just the bookmark neighborhoods. A
displaced target triggers a shared index of line fingerprints for relocation.

On FreeBSD and Linux, settings live in $XDG_CONFIG_HOME/crumbwriter/settings.ini
or ~/.config/crumbwriter/settings.ini. On Windows and macOS, the editor
stores its INI file in Qt's per-account settings location. The last document
is a local file URI. Local single-instance forwarding uses a user-scoped
connection and a lifetime lock. The system window manager controls geometry
and decorations. The attached F1 reference, Settings and bookmark windows
can stay modeless while the manuscript is open.

Building and publishing the installers
-------------------------------------

The Windows and Mac jobs use CMake, Ninja, pkg-config, Qt 6 Widgets and
Network and XML, GLib/GIO, libarchive, Hunspell and a C11/C++17 toolchain. The CMake project
reads its version from src/qt/buildinfo.h, the same source used by About.
From an MSYS2 UCRT64 shell on Windows or a native Mac development shell
with the matching dependencies, use these commands in the repository.

    cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
    cmake --build build
    ctest --test-dir build --output-on-failure

The resulting development executable uses the local dependency installation.
For a distributable copy, the platform workflows stage the runtime,
plugins, dictionary, licenses and corresponding sources. Windows uses
Inno Setup. On macOS the build produces native Apple silicon and Intel
copies, combines their executable code into one universal app, signs the
finished bundle locally and places it in a disk image.

Native runner labels, dependency installation and packaging commands
live in .github/workflows/windows.yml and .github/workflows/macos.yml.
The installed-program test runs the packaged executable with --smoke-test.
It opens a real editor window, decodes the icon, reads the embedded license,
checks US spelling, a curly-apostrophe contraction and a real thesaurus lookup, and round-trips a
Unicode-named manuscript with its backup and personal dictionary. The
Windows and Mac checks require the dictionaries shipped inside that package.
Ubuntu and FreeBSD package tests install on a clean target, upgrade an older
package fixture, launch and smoke-test the installed editor, and remove it.
They verify personal manuscripts and companion files survive the lifecycle. Some minimal Ubuntu installations omit optional
documentation when unpacking packages. Check the manual and notices in the
download itself and the mandatory copyright file after the package is installed.
Fresh runner jobs exercise installing, updating and removing the desktop app.
The public release workflow also runs the FreeBSD and Linux suites.
A release request must identify a commit already on the default branch,
and the requested version must match buildinfo.h. A v2.4 tag or a
release/v2.4 branch requests version 2.4. A manual release workflow on the
default branch can also take its version from buildinfo.h.

All required platform jobs must pass before publication. The publishing job
collects their tested installers and matching source archives, computes
SHA256SUMS, and obtains GitHub build attestations for all seven packages and the
checksum list. It uploads everything to a draft, checks the uploaded file
digests, and publishes the release. It then verifies GitHub’s immutable
release record and all seven downloadable packages with gh release verify and
gh release verify-asset. A correction to a published build uses a new version.
The installed editor and ordinary downloads do not require GitHub CLI.

This repository has enabled immutable releases. The repository control is
under GitHub Settings > General > Releases > Enable release immutability.
For a new fork, enabling it before publication protects subsequent releases.
GitHub locks each published release's tag to its source commit and prevents
changes to the attached files. The workflow independently refuses to replace
an existing public release. GitHub's signed build record verifies which
repository and workflow produced a downloaded file, including a copy
acquired elsewhere.
    https://docs.github.com/en/code-security/how-tos/secure-your-supply-chain/establish-provenance-and-integrity/prevent-release-changes

Verification
------------

Use make check-core for the parser and storage tests without a display. In a
graphical session, make check runs the core and Qt suites. make check-gui
runs the model, document store, bookmarks, synonym lists, spelling,
navigation, editor, live movement selections, search, window, appearance,
layout, symbol picker, interactive synonyms and resize
tests. The resize test measures a completed paint after typing in a moving
window with recognized aliases on every paragraph and checks the actual text
and caret. The installed-package smoke test verifies the embedded symbol
catalog by searching for U+2661.
The layout suite opens two manuscripts under simulated tiling and reopens
a saved floating window after its monitor disappears. It checks that the
width fits the available display and the saved height is recovered.
The same Makefile supports FreeBSD base make and GNU make.

Visual checks for controls and windows
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Whenever a control or window is added or changed, open it by its usual
keyboard route in both Light and Dark. Inspect its parent window, menus,
and any dialog it opens. Check empty prompts and typed text, selections,
focus, enabled and disabled actions, icons, and the fit of labels at a
narrow window width. Switch back to Follow desktop and check the native
appearance. Include the affected view in the native appearance audit so
the change can be exercised again.

The audit drives the editor with a disposable manuscript. On FreeBSD and
Linux, build it with make tests/qt/test-gui-audit. In an X11 desktop,
these commands capture either just Settings or the full application:

    ./tests/qt/test-gui-audit --platform-name xcb --output /tmp/cw-settings --view 'settings-*'
    ./tests/qt/test-gui-audit --platform-name xcb --output /tmp/cw-appearance

The CMake target is also called test-gui-audit. Use its executable with
--platform-name windows on Windows and --platform-name cocoa on macOS.
Each theme gets its own PNG images and report.json. The report records
the Qt version, platform, measured contrast, and failed checks. Review
the rendered images as well as the numbers. A readable menu can still
show the wrong symbol, and an offscreen test can miss native painting.

Windows, macOS, FreeBSD, and Linux. For changes to shared icons,
styles, or palettes, run the full audit on all four. Inspect the main
window, both manuscript modes, the search and panel menus, and every
auxiliary window. The native CI jobs preserve the pictures and reports
as gui-audit artifacts, including available evidence from a failed run.
Correct each defect, repeat its focused check, and rerun the affected
platforms and themes. Before a cross-platform appearance release, review
the four-platform full run on the revision being shipped.

Check the six command icons in Open and Save As, including Forward after
visiting two directories and the selected List View and Details buttons.
File-type artwork comes from the desktop. Inspect ordinary and selected
file rows and verify the filename is readable in each.
Check thin file-type artwork at 100%, 150%, and 200% display scaling.

The full run also captures the main window, sidebar searches, Bookmarks,
and Insert Symbol after returning to Follow desktop. Use --theme desktop
--view main for the main window alone. Compare the sidebar's placeholders
and selection with a stock input field on
the same desktop. A desktop may supply very faint placeholder text.

Focused maintenance checks for the 2.6 controls
------------------------------------------------

When a control changes, reproduce its normal keyboard path with the
native GUI audit in light and dark on FreeBSD, Ubuntu, Windows and macOS.

selection and menu states. For changes to shared colors, fonts, menus or
